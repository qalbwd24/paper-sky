# 纸翼追逐 · 四人联机与个人体验

## 本地试玩

在 `online` 目录运行 `node server.cjs`，访问 http://127.0.0.1:8770/chase/ 。首次启动前，在 `online` 目录运行 `npm ci --ignore-scripts` 安装依赖。

每位玩家使用独立浏览器身份（不同设备、不同浏览器配置或独立无痕会话），输入昵称并选择皮肤。房主创建房间并复制邀请链接，朋友打开后加入。公开房间可从大厅加入，邀请房间需要房主分享的链接。加入前可以填写自己的昵称。最多四个席位，至少两个席位可开始。房间支持由玩家浏览器运行的人机。

房主从成员中指定追击机并开始。Shift 加速、Ctrl 减速，Ctrl 优先；WS / IK / 方向键控制俯仰，AD / JL / 左右键转弯。追击机巡航 44、冲刺 68、减速 26 m/s。逃逸机巡航 48、减速 28 m/s。手机可用浮动摇杆，在菜单切换左右手。实际速度越高，转向和俯仰越缓。起飞、爬升、碰撞会让实际速度暂时低于档位速度。

前向半角 25°、50 米内无遮挡，连续锁定 2.3 秒自动发射导弹。导弹被墙拦截不算捕获。命中后在服务器同一步中：旧追击机捕获数 +1，被捕获者被捕获数 +1；后者变成追击机并在起点以 8 m/s 重新起飞，前者在原地变成逃逸机。双方获得 3 秒保护。其他人的身份和位置不变。每位玩家的捕获 / 被捕获计数显示在房间列表及个人状态栏；重连保留，房主重新开赛清零。

擦碰速度的切向保留系数：逃逸机 0.90，追击机 0.70（此前都是 0.78）。墙壁法向弹性分别 0.11 / 0.07，地面 0.13 / 0.10，正撞仍损失大部分动能。不同皮肤统一使用约 1.48 m 长、0.91 m 翼展的纸飞机碰撞包络，避免皮肤影响胜负。比赛限制在折纸都会，不使用跨层折跃门。皮肤可在比赛中切换。

## 个人体验

从游戏入口选择个人体验，可独自飞行或加入 1–3 架人机。暂停菜单可切换正式参数与原参数，也可选择捕获后互换或始终由玩家追击。个人体验在浏览器运行。

## 断线与权限

- 房主只能管理自己的房间；服务器检查房主身份和房间版本，其他玩家不能指定追击机、重开或解散。
- 关闭标签或断线保留席位 60 秒，房间冻结等待；重连恢复原身份、位置和计数。超时释放席位，房主离开时按加入顺序转交房主；追击机离开则指定剩余首位玩家，不足两人转为等待。主动离开立即释放席位。房主解散通知所有连接。
- 身份是 HttpOnly Cookie，与 Caddy 共用网站密码不同。相同浏览器配置的两个标签视为同一玩家，后打开的连接替换旧连接。
- 邀请令牌放在 URL fragment，不进入 HTTP URL；服务器存哈希。普通列表不含凭据或邀请令牌。请求与 WebSocket 都检查 Origin，动作限频、消息限长，静态文件严格白名单。
- 私有房间状态默认写入 `online/private-data/rooms.json`；云端必须用发布目录之外的 `DATA_FILE`。每 5 秒原子保存，正常退出刷新；突然断电可能损失最近几秒。服务重启后保留房间身份和计数，但全部等待重连，60 秒无人返回便清理。测试使用独立内存房间，不读取正式数据。

## 两核 2 GB 的开销控制

服务端不初始化 WebGL、相机、材质渲染或 AI。地图种子固定，碰撞空间索引仅构建一次，所有房间共享。单个 Node 进程：物理 60 Hz、每房最多 4 人、状态 20 Hz；默认最多 2 间房，不为每位玩家复制地图。空房、未开局和等待断线重连的房间不运行物理。关闭 WebSocket 压缩，控制消息与发送积压上限；客户端预测、服务器确认后重放未确认输入，其他飞机使用约 120–280 ms 的自适应服务器模拟时间插值缓存。

`node benchmark.cjs`：本机四人真实地图模拟 60 秒，平均每步约 0.514 ms、P95 0.788 ms、RSS 137 MB，四人 JSON 推送估计约 175 KB/s。属于本机 Node 基准，不等同于腾讯云两核主机的测量。`browser-results.json` 是包含 Playwright 驱动的进程，内存会更高，不应直接当纯服务器占用。

部署后检查 `/chase/api/health` 的平均/最大 tick、RSS、事件循环延迟与积压次数，并查看 systemd 实际 CPU/内存。先开放 1—2 个房间；如果其他游戏同时活跃或云端 P95 延迟上升，先将 MAX_ROOMS 降为 1。服务示例限制 384 MB 内存和最多 75% 的一个 CPU 核；不是承诺公网网络时延或长期性能。

## 检查与借用代码

- `npm test`：房主权限、四人上限、邀请、60m / 1.2s 锁定、遮挡、命中原子换位、计数、重生保护、角色速度与碰撞差异、持久化、HTTP/WS 来源及输入验证、断线恢复。
- `node check-browser.cjs`：本机四个独立 Edge 身份，房间、四种皮肤、角色指定、Shift/Ctrl、服务器输入、连续锁定动画、换位、重连与可见远程飞机。捕获段使用静止位置夹具隔离判定和网络动画；不代表自动追逐平衡测试。
- PowerShell `$env:LATENCY='1'; node check-browser.cjs`：收发各添加 125 ms 延迟，验证约 250 ms 往返时的规则同步与预测。仍需真实跨设备、跨网络验收，抖动与丢包不等同于固定延迟模拟。

复用 [ws](https://github.com/websockets/ws)（MIT）处理 WebSocket 帧和连接，浏览器使用[原生 WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)。预测、确认与平滑纠正参考 [Gaffer 的 Networked Physics](https://gafferongames.com/post/networked_physics_2004/)。Three.js、现有 FlightCore / FlightContact / Labyrinth 碰撞索引继续共用，没有另写网络协议底层或另建地图模型。
